# 다음 개발 순서

## 0. Godot 전환과 첫 원정 시제품 — 구현

고정 버전 엔진과 실행 도구, Windows 내보내기, 캠프·유적 장면, 이동·점프·회피·기본 공격·내려찍기,
바닥 경고 적 셋, 인부 둘의 동행·작업·운반, 캠프 정산, 한글 HUD, 자동 검사를 준비했습니다.
이 단계는 수 분 안에 핵심 흐름을 확인하는 장면이며 완성 던전이나 기존 게임 전체 이식은 아닙니다.

## 0.5 등불 안전 구역 — 구현

안전 구역을 하드코딩된 좌표 대신 등불 빛으로 바꿨습니다. 전진 등불 세우기·옮기기, 기름에 따른 반경 축소,
빛이 물러나면 작업 일시 정지, 캠프 기름 보충을 자동 검사로 확인합니다.
남은 일: 유적을 실제로 어둡게 보이게 하는 조명·안개, 기름 소모를 보상과 연결할지 결정, 플레이어 대기 시간 채우기.

## 0.7 원정 수직 슬라이스 — 구현

출발 야영지 → 행군 2구간 → 전진 기지 → 유적. 구간마다 게시판에서 퀘스트 하나(토벌/등불지기, 기지는 운반/방어),
맡지 않은 일은 등불꾼·경비대가 대가를 치르고 처리. 연속 퀘스트 하나. 원정대 300명·노새 40·짐마차 30은 숫자 + MultiMesh 군중.
나무·풀·길 돌을 MultiMesh로 바꿔 지도를 3배로 늘리고도 드로우콜이 1345에서 578로 줄었습니다(RTX 5070 Ti 노트북 기준).
행군은 구간마다 지점 세 개, 지점마다 역할별 연퀘 단계(kill/light/visit)로 나뉘며 단계 사이마다 행렬이 실제로 전진합니다.
스크립트 플레이(봇이라 사람보다 빠름) 기준 행군 약 1분 55초, 기지 약 50초입니다. 목표 분량까지는 march_plan.gd에
지점과 단계를 계속 더하고, 지도 길이와 단계 종류(구조, 수리, 호위 등)를 늘려야 합니다.
지점마다 NPC 조의 작업과 행군을 8~14초 기다리는 구간이 있어, 이 시간을 채울 거리가 필요합니다.
대열은 약 190m(사람 4열 + 짐노새, 짐소가 끄는 마차)로, 걸을 때 다리·바퀴가 움직입니다. 행군 중 프레임 비용은 약 +0.8ms입니다.
남은 일: 행렬과 플레이어의 충돌, 어둠의 시각 표현, 식량을 결과·선택과 연결,
구간 수와 퀘스트 종류 확대, 사람이 직접 하는 플레이 테스트.

## 1. C 캐릭터와 전투 동작

공통 스켈레톤을 사용하는 주인공·목수 두 명의 GLB와 기본 애니메이션을 만듭니다.
주인공의 무기 궤적과 손잡이, 목수의 작업 도구 접촉, 짐 운반 자세를 먼저 확인합니다.
완료 기준: 같은 장면에서 이동·전투·작업 모습이 자연스럽게 이어짐.

## 2. 좋아했던 전투의 재구성

돌진 → 내려찍기 → 날아차기 → 가로베기를 실제 모델에 맞춰 연결합니다.
기술별 단축키, 회피 중 연계 보존, 짧은 입력 예약과 후딜 취소를 설계합니다.
현재 코드의 기본 가로베기는 4단 콤보 마무리 기술을 이식한 것이 아닙니다.
기존 웹 버전의 수치를 무조건 복사하지 않고 조작감부터 맞춥니다.

## 3. 원정 하나를 10~15분짜리로

폐광 내부 2~3개 구역, 통로 복구, 다음 안전 구역까지 인력 이동, 자원 선택과 운반 우선순위를 추가합니다.
임의의 대기 시간보다 주변 변화와 동료의 실제 작업이 보이게 만듭니다.
완료 기준: 플레이어의 전투가 동료의 일을 열어 주고, 회수품이 실제 정착지 자원으로 연결됨.

## 4. 저장·거래·건축

버전 있는 세이브 구조를 먼저 만들고 재고·교환·건축 부품을 연결합니다.
직접 채집 외에 원정 보상과 NPC 거래로도 재료를 얻을 수 있도록 합니다.
새 건물이 길찾기를 막는 상황, 재접속 시 NPC의 작업 복구를 함께 검증합니다.

## 5. 습격과 원정 보스

아군·적 전투병이 공유하는 기술 데이터, 원정 보스의 예고 패턴, 캠프 방어를 확장합니다.
LLM은 대화의 선택지로 남겨 두고 동료의 이동·작업·전투에는 요구하지 않습니다.
멀티플레이와 거대 오픈월드는 현재 범위에 넣지 않습니다. 세금 같은 복잡한 유지비는 식량 하나로 시험한 뒤 결정합니다.
